# Localization

Use this page for UI copy, translation changes and language expansion.
Current rule: translate at render/request boundaries; preserve user text and unknown diagnostics.
Read [catalogs](#catalogs-and-formatting) for frontend changes, [copy](#english-copy-rules) for wording,
[locale](#locale-contract) for resolution bugs, or [verification](#verification) for checks.

## Catalogs and formatting

The authoritative catalogs are [English](../web/src/i18n/en.ts) and [Chinese](../web/src/i18n/zh-CN.ts);
keys and interpolation contracts come from [catalog.ts](../web/src/i18n/catalog.ts).
Translate whole sentences with named parameters. Use shared action keys where appropriate.
Use the reactive hooks in [index.ts](../web/src/i18n/index.ts); never cache translated text at module initialization.
Store message identities for errors that must change language while visible.
Plural forms must carry the same parameters; Chinese may use identical forms.
Use [format.ts](../web/src/i18n/format.ts) for numbers, byte sizes, durations and dates.
Keep protocol names and SI units unchanged.

Go messages and localizable errors live in [internal/i18n](../internal/i18n).
Render at the request boundary while preserving the JSON error contract and unwrap chain.
Events retain message identities so a later locale change can render them again.
Known old helper diagnostics are mapped by [legacy_helpers.go](../internal/i18n/legacy_helpers.go);
unknown diagnostics and user names/paths pass through unchanged. Do not translate them by guessing.

To add a language, add catalogs in both layers and register it in their resolvers and the language chooser.
Run parity and behavior checks; component-specific catalogs and another runtime dependency are unnecessary.

## English copy rules

Use US spelling, sentence case and the product spelling from the English catalog.
Buttons use verbs. Progress uses one ellipsis. Errors explain the failure and next action without blame or an “Error:” prefix.
Labels, buttons, titles and single-sentence descriptions omit the trailing period; multi-sentence paragraphs retain punctuation.
Apply the same punctuation rule to Chinese.
Reword overflowing English before changing layout.
Use “target computer” in prose and “Target” in tight labels; reserve “host” for technical network concepts.
Write counts as natural plural phrases. Use “Power budget” for negotiated supply capacity, not measured consumption.
Use “Passthrough” for 透传, “Eject” for 弹出 and “Image” for disk images.
Other page names and terms have one authority: the English catalog.

## Locale contract

Resolution, persistence and fallback are defined in the frontend [resolver](../web/src/i18n/index.ts)
and server [i18n package](../internal/i18n). The manager and gateway share the language preference;
each KVM application's language remains independent.
Language changes must refresh active read effects and visible errors, including an open account form.
Non-primary catalogs load before first render or before the switched language becomes visible.

## Verification

Run the frontend build plus [source audit](../web/tests/i18n-source.mjs) and [behavior suite](../web/tests/i18n.mjs).
Browser fixtures intercept APIs and external traffic; they do not validate hardware.
Use [i18n-screens](../web/tests/i18n-screens.mjs) for the review matrix and
[production](../web/tests/production.mjs) for built assets and localized login titles.
Check overflow and clipped labels in both languages and mobile layouts.
Production asset MIME types matter: an SVG served as a generic binary may not decode.

Shared board helper changes belong to the public repository's own review scope.
Manager mappings must continue accepting older installed helpers during upgrades.
Historical rollout evidence: [localization record](https://github.com/vim4-kvm/vim4-kvm/blob/main/docs/bringup/2026-10-29-manager-i18n.md).
