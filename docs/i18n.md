# Localization

English is the primary language; Simplified Chinese is also supported. All
pages, shared controls, authentication and gateway responses, and recorded
events use catalogs. Global frontend and Go source audits enforce the catalog
boundary. User-provided names and unknown external diagnostics are preserved.

## Locale contract

Locale IDs are `en` and `zh-CN`, with `en` as fallback. The browser checks a
saved `vim4-manager-language` localStorage value first, then checks
`navigator.languages` (any `zh*` selects `zh-CN`), then defaults to `en`.
Selection updates the document language and the `vim4_lang` cookie with
`Path=/; Max-Age=31536000; SameSite=Lax`. Storage events update other tabs.
Cookies are shared between the manager and gateway ports. The main title stays
`VIM4 KVM`; login uses `Sign in · VIM4 KVM` or `登录 · VIM4 KVM`.
The server checks the same cookie, then Accept-Language quality preferences,
then English. Invalid cookies defer to the header; `q=0` ranges are ignored.

## Catalogs and formatting

`web/src/i18n/en.ts` is the single English source catalog, imported normally
and bundled with both entries. Other catalogs load as dynamic chunks before
first render or before a language switch becomes visible. `zh-CN.ts` uses
`defineCatalog` to verify keys and interpolation parameters at compile time.
Use feature names such as `login.*`; shared actions belong in `common.*`.
Translate whole sentences and use `{name}` parameters. `t` enforces parameters;
`useT` and `useLocale` subscribe to live changes. Avoid rendering translated
constants once at module initialization. Store message identities for errors
that must update when the user changes languages.

Plural entries use `one` and `other`, selected with `Intl.PluralRules`. Chinese
can use identical forms. Keep the same parameters in both forms.
Use `i18n/format.ts` for locale-aware numbers, SI byte sizes, durations, dates,
24-hour times, and relative times. English dates use month names to avoid
US/EU ambiguity. Durations omit zero units and show at most two units. Compact health cells use “{used} / {total}”; other usage summaries retain “of … used”. Keep protocol names, SI units, and °C unchanged.

The Go `internal/i18n` package carries `Message{Key, Args}` and localizable
errors with English `Error()` strings and an unwrap chain. Render at request
boundaries with `RequestLocale`; preserve the existing JSON `error` property.
`Events.AddMessage` stores templates and arguments; `List(locale)` renders a
copy without changing stored events. Board watchers and actions record message
identities; the plain-text `Add` method remains available for compatibility.

Application descriptions, platform service names, and shipped EDID preset
descriptions render at the request boundary. Locale changes restart the active
read effects immediately, including status, Wi-Fi, Tailscale, NAS storage,
NAS sessions, media, EDID, kernel, updates, and account reads.

To add another language, add one catalog in each layer, register its locale in
the resolver and language choices, and run parity and behavior checks. No
component-specific translation files or new runtime dependencies are needed.

## English copy rules

Use US spelling and sentence case. Preserve NanoKVM, JetKVM, One-KVM, PiKVM,
HDMI, USB-C, EDID, HDR, Wi-Fi, Tailscale, SMB, NFS, and PD casing.
Buttons use verbs: Save, Apply, Connect, Sign in, Sign out, Restart service.
Progress uses a single ellipsis: Saving…, Connecting….

Errors explain what failed and the next action, without blame or an `Error:`
prefix: “Couldn't connect to the board. Check the network and try again.”
Prefer concise familiar language over abbreviations. Labels, buttons, and
titles have no trailing period; descriptive sentences do.
Reword overflowing English first; change layout only when needed.
Use “target computer” for the computer controlled by the KVM; use “Target” in
tight labels. Reserve “host” for technical network concepts such as HTTP hosts.
Summaries use “{used} of {total} used” and “{free} free on system disk”.
Write counts as natural phrases with plural forms, such as “1 file · 2 folders”.

## Offline verification and helper inventory

Run the normal frontend typecheck/build, `node web/tests/i18n-source.mjs`, and
`node web/tests/i18n.mjs` with the existing local Vite and Playwright setup.
The browser entry intercepts API calls and aborts external requests. It covers
language resolution, persistence, cookies, cross-tab changes, live updates,
and login controls. `i18n-screens.mjs` generates the complete review matrix and
index in `/tmp/i18n-codex/final3/`: every page in both languages, desktop light
and dark, mobile light, overview at 1280px, language menus, and error/empty
states. It checks text overflow and clipped button labels. Existing suites pin English;
locale tests also exercise Chinese and live switching with an open account form.
Run `node web/tests/production.mjs --screens` after building to capture the
matrix through Vite's production preview. It verifies every main/login image,
both SVG favicons, and localized login titles. Preview supplies asset MIME
types; serving SVG as `application/octet-stream` breaks browser image decoding.

Storage, Wi-Fi, Tailscale, and update helper diagnostics use English.
Manager-side legacy tables accept older installed helpers' Chinese diagnostics.
Storage JSON diagnostics and Tailscale jobs render at the HTTP boundary;
user-controlled names, paths, and unknown external diagnostics are preserved.
EDID and passthrough helpers also emit English; their previous Chinese
diagnostics remain recognized during upgrades.

Shared modules `../board/vim4media.py` and `../board/vim4boot.py` emit Chinese
media/kernel failures. Their known messages are mapped by the manager's
`internal/i18n/legacy_helpers.go`, including the kernel-checksum prefix.
Unknown output passes through unchanged. The helper also imports `vim4video` and invokes
`/usr/libexec/vim4-passthrough`, whose status reasons use the same legacy
mapping. In-repository helpers have been updated; shared-board files remain
unchanged. Proposed shared-board copy changes are recorded in
`/tmp/i18n-codex/board-followup.md`. Manager-side legacy mapping preserves
support for previously installed helpers.
Do not change the shared board repository without the requested approval.
